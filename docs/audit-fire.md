## Bug（桩实测复现）

### FB1 烤干/干燥潜热取错系数 → 热量不守恒 + 土温变负（−61° ~ −295°）

- 位置：`FireParticle.cs` `TryDryWetSoil` 末行；**同源错误也在 `WetSoilParticle.cs:105`**（N1 提交引入，两处同一份修复）。
- 机理：两处都按 `-HumidityField.LatentHeat(T) = -5.5T` 从土壤取热。5.5 是**水↔大气**的热容差（C_水 6.5 − C_空气 1），只对沸腾/蒸发成立；湿土→干土的热容差只有 **1.2**（2.0 − 0.8），温度连续只需取 `1.2T`。
- 桩实测（火贴湿土，1 帧后读回）：

  | 湿土初温 T | 烤干后土温 |
  |---|---|
  | 20 | 5.6 |
  | 60 | **−61.1** |
  | 100 | **−127.8** |
  | 200 | **−294.6** |

  超发的 4.3T 把该格全部热量掏空后继续扣。连带效应：火自己的注入热被负温格吸走（T=60 湿土旁的火 1 帧后只有 76°，而非单格火应有的 ~250°）。
- 修法方向：按相变双方热容差结算 `AddHeat(wx, wy, -(WetSoilCapacity - SoilCapacity) * T)`（即 −1.2T），两处同修；补「烤干前后总热守恒 + 干燥后土温为正」回归测试（现有 `Fire_DriesAdjacentWetSoil_ThenIsQuenched` 只断言了水守恒与帧数，漏检此项）。

### FB2 火自灭（Clear）湮灭本格全部水汽 → 总水不守恒

- 位置：火的所有熄灭路径走 `world.Clear`；根因在 `ParticleWorld.Set` 的气体分支 `_humidity.ResetAt(index)`（旧 N6 缺口，火把它从理论问题变成实战路径）。
- 桩实测：水池 34 格 + 3 格火，逐帧对齐死亡帧——**总水损失精确等于死亡帧火格持有的水汽**（最后一格火死亡时带走 1.7576 份，场景总水 44.00 → 42.24，−4%）。火格湿度越高损失越大。
- 注意：`0249665` 新增了两条 Clear 路径（压顶立灭、无支撑坠落熄灭），损耗面比初版更大。
- 修法方向：自灭前先 `EvacuateHumidity`（把本格水汽播给四邻气体格），或自灭改走保留湿度的路径；若判定为可接受的世界语义，至少写进文档并补定量测试锁住损耗（当前 0 覆盖）。

### FB3 烤干没有温度门：0°C 的新生火也立刻烤干湿土

- 位置：`FireParticle.TryDryWetSoil` 只查湿度两道门（IsAirSaturated / SpreadUnitIntoAir），不读温度；对照 `WetSoilParticle.cs:81` 的自然干燥要求 `T ≥ DryingTemperature(60)`。
- 桩实测：火第 0 帧（自身 T=0.00）就完成烤干并摊出 1 份水汽；湿土压石加热到 200° 自然路都不干，旁边一个冷火 1 帧烤干。**冷火 = 万能烘干机**。
- 修法方向：加与湿土自蒸发一致的温度判据（本格或目标格 T ≥ 60，或引入独立点燃/烘烤温度常量）。

## 设计观察（行为正确但值得写明 / 确认）

- **FD1 压顶立灭无法区分「砸落」与「静置」**（`0249665`，有意为之）：实现是「正下方是石头/沙/水 → 当帧直接熄灭」，因此**手刷在石面/沙面/水面上的火同样一格都活不过**（投放锚点合法、下一逻辑帧即灭）。提交信息表明知情（侧邻烤热测试因此改为沙石放两侧）。建议在 `docs/ParticleTypeInterface.md` 把「火无法停留在石头/沙/水面上」写成显式行为，免得将来被当 bug 报回。
- **FD2 火柱塌落机制与注释措辞**：`CanGasEnter` 密度条件是 `self ≥ other`（0.6 ≥ 0.6 成立），无支撑火柱实为「与下方火等密度互换 + 1/5 熄灭骰逐格消亡、空格被上方火回填」，不是头注释所说的「整体下沉」。行为没问题，措辞略有美化。
- **FD3 火能烧沸紧邻的水池**（需确认设计意图）：火的设计上限 400° 只是格温上限，注入热经传导到水里，贴水的火 ~1 秒寿命也足够把邻水煮沸。桩实测 44 格水 + 3 格火 130 帧后 14 格水变成水汽（总水守恒但分布大变，差额全部来自 FB2）。若不想要，考虑火→液体传热限幅或更快的贴水熄灭。
- **FD4 视觉表现不像火**（用户观察）：火当前只有「无支撑才下沉」的运动（永不主动上腾/摆动），视觉扰动只有本格 shade 逐帧 ±1 随机游走——格与格之间无相关性，整体是静态色块闪烁，没有火焰的上升、摇曳、形态收束感。属表现层改进空间，无正确性问题。

## 测试问题

- **FT1 精确帧断言脆弱**：`FireParticleTests.cs:322/358` 的 `AreEqual(29/17, steps)` 绑定整个 RNG 消耗序列（含每次 Set 的 shade 抽样），任何改动都会连带击穿。建议宽化到窗口断言 + 一条「同世界重放两次逐帧一致」的确定性断言，或把帧号集中成命名常量。
- **FT2 热守恒/速率/生产参数三处空白**：烤干用例不断言热量（正是 FB1 漏检的原因）；蔓延/熄灭只断言存活或精确帧号、不锁经验频率（IgnitionDenominator 改大也可能过）；所有热学用例跑在 HeatMap 默认参数下，生产资产（Conductivity 0.24 / RadiativeLoss 0.05 / ε_air 0.1）下的 400° 上限与致死线零验证。
- **FT3 注册顺序断言弱于契约**：`AreEqual(Fire > HumusSoil)` 防不住「插到 AquaticPlant 与火之间」——应断言 `Fire == AquaticPlant + 1`。
