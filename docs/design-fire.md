## 0. 为什么重做

v1 的火（审计 FD4）**不像火**：无支撑时只会整体下沉，永不主动上腾；视觉扰动只有本格 shade 的 ±1 随机游走，格与格无相关性，整体是静态色块闪烁——没有上升、没有摇曳、没有「底宽顶尖」的形态。同时审计坐实了三个正确性 bug（FB1 潜热系数错取导致热量不守恒与负温、FB2 自灭湮灭水汽、FB3 冷火无温度门烤干湿土）。v2 在修掉 bug 的同时重做运动与视觉模型。

## 1. 设计目标

| 目标 | 验收直觉 |
|---|---|
| **像火** | 贴燃料的火烧在原地，向上抛出火舌；火舌上升、左右摇曳、越升越暗、顶端自行熄灭——整体呈底亮顶暗、底宽顶尖的锥形 |
| **颜色即温度** | shade 不再是独立随机游走，而是本格温度的分档映射（亮黄 = 热、暗红 = 凉），视觉与热学同源 |
| **守恒** | 烤干湿土热量守恒且土温不为负；火熄灭不带走水汽；点火不湮灭目标格水汽 |
| **确定性** | 同种子同命令逐格可复现；运动帧零随机流消耗（错拍用确定性哈希）；RNG 消耗表可枚举 |
| **不破坏既有契约** | 点燃蔓延、淬熄三档、压顶立灭、投放资格、注册顺序、`Cell` 4 字节布局全部保留 |

## 3. 角色模型：附着火与游离火

v2 把火分成两种行为角色，**同一 typeId、同一调色板**，由每帧环境判定、无持久状态：

- **附着火**：八邻内有固/液（燃料或任何实体，**火不算附着物**，同 v1）。定在原地燃烧；注入热量；概率点燃邻接的草；向**上方气体格**抛射火舌（§5.6）。
- **游离火**：八邻无固/液。**不再下沉**（删除 v1 的 `TrySink` 路径），改为**上升 + 摇曳**（§5.8，逻辑帧末尾）；不注入热量，靠余热上升、随传导冷却；冷却到熄影线或摇中熄灭骰即消失。游离火就是「火舌」。

角色每帧重判：附着火的燃料被烧光/被浇灭后，它下一帧自动变游离火，上升一二格后熄灭——火焰「脱离残渣上扬消散」是涌现的。

### 为什么不是下沉

现实火焰因热浮力上升；v1 的下沉是「密度 0.6 > 大气 0.5」的机械后果，恰好与直觉相反。v2 让运动规则显式向上，密度维持 0.6 不变（保证大气推不动火、沙/水仍可置换覆盖火——rank 与置换契约不动）。

## 4. 运动设计（拍板：上升移入 `OnLogic`，`OnMotion` 留空）

§7.3 已拍板：**不动 `ParticleWorld`**，不引入运动相位概念。火的全部位移都在逻辑帧（20 Hz）内完成，运动帧对火零操作：

- **附着火**：`OnMotion` 与 `OnLogic` 的位移部分都为空——定在原地燃烧（同 v1）。
- **游离火**：`OnMotion` 留空；上升 + 摇曳作为 `OnLogic` 的最后一步（§5.8），每逻辑帧至多上升一格 → 上限 20 格/秒。

代价与收益：上升节奏与逻辑帧同步，视觉上与色带刷新（§5.1 也按逻辑帧回写）同帧发生，二者天然合拍，无「移动了但颜色没跟上」的错帧；省掉世界侧改动与相位暴露。`OnMotion` 按契约留空是常态，不违反任何架构约束。

## 5. 逻辑设计（`OnLogic`，20 Hz）

顺序即契约，每格每逻辑帧：

### 5.1 颜色回写（取代 v1 的 shade 随机游走）

每逻辑帧把 shade 重算为**本格温度的分档**，再加 ±1 哈希抖动（同 v1 的 `(x,y,Tick)` 哈希，不消耗随机流）：

| 温度 T | 基准 shade | 色 |
|---|---|---|
| ≥ 300 | 0 | 亮黄 |
| 200 – 300 | 1 | 黄 |
| 130 – 200 | 2 | 橙 |
| 80 – 130 | 3 | 深橙 |
| 40 – 80 | 4 | 红 |
| < 40 | 5 | 暗红 |

抖动后 clamp 到 `[0, 5]`。`ParticleWorld.Set` 的初始抽样被下一逻辑帧覆盖，无需改世界。效果：附着火底部恒亮黄；游离火越升越冷、色带自动向暗红迁移；火焰轮廓的颜色梯度 = 温度场，视觉与热学永远一致。

### 5.2 放热（仅附着火）

附着火且本格温度 < `PeakTemperature`（400，不变）时注入 `FireHeatPerTick`（250，不变）。**游离火不注入**——这是 v2 的关键变化：离焰即离热源，火舌上升即冷却，配合 §5.1 自然得到「顶尖暗红消散」。单格火的设计平衡温度因此只对附着火成立，审计中「400° 上限」的语义不变。

### 5.3 八邻扫描（只读，不摇骰）

同 v1：第一格草（燃料）、第一格湿土（干化目标）、淬熄触发、附着物判定。顺序与数组不变。

### 5.4 干化（修 FB1 + FB3，先于熄灭骰）

贴湿土时先判**温度门**（FB3）：**本格（火）温度 ≥ `DryingTemperature`（60，复用 `WetSoilParticle` 同名常量）才允许烤干**。新生火第一逻辑帧 T≈0 不烤干；注入 250 后第二帧即越门，实际延迟约 0.1 秒，观感无差，但「冷火 = 万能烘干机」消失。

烤干结算（FB1，两处同修——`FireParticle.TryDryWetSoil` 与 `WetSoilParticle.OnLogic` 受热蒸发分支）：

```
潜热 = (WetSoilCapacity − SoilCapacity) × T = 1.2 × T
world.SetPhase(wx, wy, Soil);
world.Heat.AddHeat(wx, wy, −1.2 × T);
```

5.5T 是**水↔空气**的热容差，只对水粒子沸腾/蒸发成立；湿土→干土的相变双方是湿土与干土，温度连续只需补 1.2T。修后烤干前后总热严格守恒、干土温度恒为正。

水汽去向不变：先确认摊得出去（`IsAirSaturated` / `SpreadUnitIntoAir` 两道门），摊不出去则原样保留，守恒优先。

### 5.5 熄灭（保留 v1 三档 + 压顶，新增冷却即灭）

> **v2.1 已改写本节：见 §12**（`QuenchDenominator` 20→5、`WaterQuenchDenominator` 5→2、新增「被包围 → 当帧窒息」、删除「烧尽骰 1/120」、有燃料一律不摇熄灭骰）。以下为 v2 原始决策记录。

1. **压顶立灭**（不变）：正下方是石头/沙/水 → 当帧熄灭、不摇骰。
2. **淬熄骰**（不变）：贴石头/沙/水/湿土 → 1/20。
3. **游离熄灭骰**（调参）：游离火 → 1/`FreeExtinguishDenominator`（v1 是 1/5，v2 建议 **1/8**，期望 0.4 秒 ≈ 上升 8 格，火舌长度适中；数值进调参表 §10）。
4. **冷却即灭**（新增）：游离火本格温度 < `EmberTemperature`（**40°**，与 shade 最暗档同阈值）→ 当帧熄灭、不摇骰。这是火舌顶端的收束机制：余热散尽的火舌必然熄灭，不会飘浮长尾。
5. **烧尽骰**（不变）：附着但无燃料 → 1/120。

每帧恰摇一次骰的结构不变（档位互斥，自上而下）。

**FB2 修复对这里的影响**：所有熄灭路径仍走 `world.Clear`，但世界的湿度语义改了（§6.2），火代码不需要任何特判。

### 5.6 火舌抛射（新增，附着火专属）

附着火、**正上方是气体/空**、本格温度 ≥ 200° 时，以 1/`TongueDenominator`（建议 **10**，即附着火平均每 0.5 秒吐一格火舌）摇一次骰，命中则 `world.Set(x, y+1, Fire)`。新火格通常无附着 → 下一逻辑帧起按 §5.8 上升为游离火。

约束：先判「上方是气体」再摇骰（B11 原则，无目标不消耗 RNG）；上方是火则跳过（火舌不叠火舌，避免垂直火柱自我无限加高）。一轮草火因此呈现「燃烧层 + 断续上窜的 2–6 格火舌」，而非静态色块。

### 5.7 蔓延（不变）

有燃料时 1/20 点燃第一格草；有燃料且不贴淬熄物时不摇熄灭骰（保证贴住的燃料必被逐格吃掉）。**但「烧光整片草」不保证（已拍板为涌现特性）**：点燃走 `Set`（草 → 火）会触发世界「有机死亡 20% 留腐殖质」规则——20% 的点燃是哑弹、直接变腐殖质而非火；腐殖质不是燃料、八邻无土时永久滞留为空洞。v1 的游离火下沉会无意中回填这些空洞续烧（同场景能烧光），v2 改上升后修复机制消失，火线在空洞处断代，零星被围死的草格成为残株（桩实测 19×6 草块烧剩 1 格）。拍板结论：接受——断代与残株本身是真实的火场涌现；测试断言相应放宽为「烧掉大部（≥3/4）+ 火全灭 + 终态只余空气/腐殖质/残草」。备选方案（点燃不留腐殖质 / 余烬下沉复燃）已评估未采纳，记录在案。

### 5.8 游离火上升（`OnLogic` 末尾，拍板方案）

仅游离火执行，是 `OnLogic` 的**最后一个动作**——熄灭骰全部结算完、确认本帧存活之后才尝试移动，将死之火死在原地、不拖着尸体上移：

1. **摇曳选向**：`(x, y, Tick)` 哈希取 2 bit——50% 正上、25% 左上、25% 右上；
2. 首选方向 `ParticleRules.CanGasEnter` 通过（火 0.6 ≥ 目标气体密度：能换进大气/空气/火，被固/液拒绝）→ `Swap` 过去，立即 return；
3. 首选被挡 → 试另一斜上；再被挡 → 本帧原地不动（**不下降**）。

性质：每逻辑帧至多一格 → 上限 20 格/秒；摇曳使火舌轨迹呈随机折线，多格并排行进即「跳动的火墙」；斜上被挡才静止让火舌贴斜面爬行、不穿实体；哈希不消耗世界随机流，FT1 的重放断言不受影响。`Swap` 之后目标格与本格都被世界打上本 tick 的处理标记（bit0 机制），同一逻辑帧内不会被重复处理。

## 6. 守恒修复详单

### 6.1 FB1 潜热系数（两处同修）

| 位置 | 现状 | 改为 |
|---|---|---|
| `FireParticle.TryDryWetSoil` 末行 | `AddHeat(−LatentHeat(T))` = −5.5T | `AddHeat(−(WetSoilCapacity − SoilCapacity) × T)` = −1.2T |
| `WetSoilParticle.OnLogic` 受热蒸发分支（C1 注释处） | 同上 | 同上 |

`LatentHeat(T)`（随温度线性）继续服务**水↔大气**相变（沸腾/蒸发/凝结），不改动。回归断言：烤干前后世界总热差 == −1.2T（±浮点容差）、干土温度 > 0。

### 6.2 FB2 世界侧统一：气体被覆盖也疏散水汽

根因在 `ParticleWorld.Set`：目标换上**气体**时直接 `_humidity.ResetAt(index)`，换上固/液时反而走 `EvacuateHumidity` 推给四邻。这不对称让「火自灭（Clear → Set 空气）」「火蔓延（Set 火盖空气）」都湮灭水汽——FB2 实测一场 3 格火的场景总水 −4%，且**点火路径同样漏**（审计只测了熄灭半）。

修法（世界侧一处，不是火代码特判）：`Set`/`Clear` 目标为气体时，若本格残湿 > 0，**也先 `EvacuateHumidity` 再清零**（`EvacuateHumidity` 提为 internal 供 Set 两分支共用）。语义统一为：**任何覆盖旧气体的写入，旧水汽都先推给四邻气体格，推不掉才留在原地**（守恒优先于「非固液格持湿」不变量，与既有固/液分支同一原则）。

连带影响面（评审需知）：大气被固/液覆盖的路径本就走 Evacuate（不变）；大气被火/大气覆盖的路径从「清零」变「疏散」——水循环守恒性只会更好，无场景会变差。`audit-water-cycle.md` 的水总量不变量测试应全绿，并新增「点火 + 自灭全程总水守恒」回归。

### 6.3 FB3 温度门

见 §5.4。判据用火的**本格温度**而非湿土温度：火是热源，门应立在热源侧；且新生火 0.1 秒后即越门，不改变「火能烤干湿土」的既有验收。

## 7. 行为决策（评审拍板）

### 7.1 FD1 → 写为显式行为

「火无法停留在石头/沙/水面上」是压顶立灭的必然推论，v2 保留压顶规则，因此该性质保留。**在 `ParticleTypeInterface.md` 与火文件头注释中写成显式行为**：手刷在石面/沙面/水面的火下一逻辑帧即灭——这是设计，不是 bug。要「石头旁有篝火」观感请用草/土做基座。

### 7.2 FD3 贴水煮沸 → 推荐限缩（A），备选接受（B）

**现状的定量机制**（为什么「贴水 ~1 秒」必然煮沸邻水）：

1. 附着火每逻辑帧注入 250 Q（T < 400 时），自身几帧内贴近 400° 软上限；
2. 热传导（生产参数 `Conductivity = 0.24`，界面导热率取两侧算术平均：(σ火 1.0 + σ水 0.95)/2 ≈ 0.975）：稳态 ΔT ≈ 400 − 20 = 380 时，火→水每逻辑帧流入约 `0.24 × 0.975 × 380 ≈ 89 Q`；
3. 把一格水从 20° 烧到沸点 80° 需要 `6.5 × 60 = 390 Q` → **约 4.4 个逻辑帧 ≈ 0.22 秒**（忽略水向邻水的二次摊薄；水体 σ 0.95 会摊热，只把所需帧数拉长，不改变量级）；
4. 而贴水的火当前与贴石头同档，走 1/20 淬熄骰，几何分布期望寿命 **20 逻辑帧 = 1 秒**——是煮沸所需时间的 **4.5 倍**。审计桩实测吻合：44 格水 + 3 格火，130 帧后 14 格水变成水汽（分布大变，差额来自 FB2）。

结论：「贴水煮沸」不是边界意外，而是当前参数下的**必然结果**——淬熄期望寿命 ≫ 煮沸所需时间。

**选项 A（推荐）：液体独立快熄档**。把**液体**从淬熄集合拆出，走独立分母 `WaterQuenchDenominator = 5`（贴水期望 5 逻辑帧 = 0.25 秒灭；石头/沙/湿土仍走 1/20）：

- 交付热量重估：火前几帧还在升温（第 1 帧 T≈250），前 5 帧平均 ΔT 远低于 380，交付上界约 200–450 Q → **多数情况一格水都煮不开，偶发 0–1 格**（水面临火嗞起一小缕白汽即灭，恰好是想要的观感）；且 1/5 几何分布下约 59% 的火活不过 4 帧，交付更少。
- 每帧仍恰摇一次骰：八邻有液体优先走 1/5；否则有石头/沙/湿土走 1/20（档位互斥，RNG 消耗表 §10 结构不变）。
- 物理直觉：水是最强灭火剂，贴水快熄比贴石头快熄更贴近经验。
- 连带效果：水边草地成为天然防火线（火烧到水线即灭）——现实且免费。
- 不受影响的既有行为：烤干湿土在熄灭骰**之前**结算（§5.4 顺序不变），贴水又贴湿土的火当帧先烤干、再可能被淬熄；「水置换火即灭」的 rank 涌现路径不动。
- 代价：不能再用火「持续烧干」小水洼——这正是目的；要烧水就持续投火，A 不堵死煮沸（概率低），只把「贴水即沸」从必然降为偶发。

**选项 B（接受现状）**：把「火能煮沸紧邻小水体」写进 `ParticleTypeInterface.md` 作为显式行为，零代码改动。适用于「火加热水体」被视为玩法的场景。

### 7.3 运动相位来源 → **已拍板：驳回，采用备选 B**

不为火的运动相位改 `ParticleWorld`：火的上升 + 摇曳全部放在 `OnLogic` 末尾（§5.8，20 Hz 上限），`OnMotion` 留空。理由：零架构改动；上升与色带回写同帧发生，无错帧。放弃的东西：60 Hz 的细分错拍（3 拍散布）——20 Hz 下火舌逐格上窜的节奏与逻辑帧同步，视觉可接受；若将来实测觉得「逐格跳」太硬，再单独立项评相位暴露，不影响本设计的其余部分。

## 8. flags / Cell / 注释订正

- **flags**：v2 火仍不占用任何私有位。文件头注释订正为事实：「bit3-4 大气风向记忆、bit5-6 种子计数占用中；本类型不使用任何位（bit7 空闲但不占用）」。
- **shade**：语义从「Set 抽样 + 随机游走」改为「**派生量**：每逻辑帧由温度分档 + 哈希抖动重算」。`Cell` 布局不变；渲染契约不变（渲染只读 shade 查表）。
- **Cell**：4 字节不动；不需要速度场；火龄/相位等全部用坐标与 Tick 的确定性函数代替 per-cell 状态。
- `ParticleEditor.cs:249` 注释同步「锚点含火链」语义（v1 已漏，本次顺手修）。

- 不做余烬粒子/新类型：注册表追加是新存档兼容负担，`OnKill`/`OnRandomTick` 留作将来扩展点。

## 12. v2.1 修订（被包围窒息 + 「任何非可燃固体」淬熄）

**动机（用户验收）**：① 火在不可燃粒子（干土 / 腐殖类 / 木头 / 树叶……）上要**更快熄灭**；② 被物质压住 / 围死时应当**熄灭**，而不是被落下的物质顶到表面「上浮」后继续烧。

**改动**

1. **淬熄集合由白名单翻成标签**：旧实现只认石头 / 沙 / 湿土，其余不可燃固体（干土 / 腐殖土 / 腐殖质 / 树干 / 树叶 / 各类种子 / 水生植物）落进「附着无燃料 → 1/120 烧尽骰」，要赖 6 秒。现改为**任何带 `Solid` 标签的邻居（草 / 花除外——它们是燃料）**都进淬熄档。
2. **速率**：`QuenchDenominator` 20 → **5**（期望 0.25 秒）；`WaterQuenchDenominator` 5 → **2**（期望 0.1 秒）。液体仍严格快于固体。
3. **新增「窒息立灭」档**（优先级仅次于压顶）：八邻**全无空气 / 气体**（被固 / 液围死）且**没有燃料** → 当帧 `Clear`、**不摇骰**。被埋死 / 封进密闭腔的火当帧闷熄；燃料是唯一豁免（草块内部的火线必须能一路烧进去——草块里八邻常全是草 / 火）。
4. **删掉 `BurnoutDenominator`**：附着 ⇒ 八邻必有固 / 液 ⇒ 有燃料走「不摇骰」、无燃料必落液体 / 固体淬熄档，该档已不可达。
5. **「有燃料就不摇熄灭骰」由「不贴淬熄物时」放宽为无条件**：旧实现里「贴淬熄物 + 带草」会先摇熄灭骰（命中即灭，邻接燃料烧不掉）；现在带草根本不摇熄灭骰——**火线推进不再被脚下的土 / 残渣随机打断**，这正是把干土收进淬熄集合后「烧光草地」验收仍成立的前提（新增 19×6 草块铺在土上的回归用例）。
6. **被压顶时仍会先「浮」一格**：位移来自世界的 rank 规则（固体换进气体格），火代码拦不住；但落下来的是石头 / 沙 / 液体时下一逻辑帧即压顶立灭，其余材料走 1/5 淬熄骰、被围死则当帧窒息——不再出现「上浮后继续烧几秒」。

**新的熄灭档位（自上而下互斥，顺序即契约）**

| # | 条件 | 结果 | RNG |
|---|---|---|---|
| 1 | 正下方是石头 / 沙 / 液体 | 当帧 Clear | 0 |
| 2 | 八邻全无空气 / 气体，且八邻无燃料 | 当帧 Clear | 0 |
| 3 | 游离火且本格 T < `EmberTemperature`（40） | 当帧 Clear | 0 |
| 4 | 游离火 | 1/8 Clear | 1 |
| 5 | 八邻有燃料（草 / 花） | 不摇熄灭骰 | 0 |
| 6 | 八邻有液体（无燃料时） | 1/2 Clear | 1 |
| 7 | 八邻有非可燃固体（无液体时） | 1/5 Clear | 1 |

**测试**：`FireParticleTests` 新增 4 例——`Fire_AnyNonFlammableSolid_QuenchesWithinWindow`（8 种不可燃材料 × 40 逻辑帧窗口）、`Fire_EnclosedByMatter_SuffocatesImmediatelyWithoutRoll`（密闭腔一个逻辑帧内熄灭 + 随机流 0 消耗）、`Fire_EnclosedButFuelled_KeepsBurning`（燃料豁免窒息）、`Fire_BurnsGrassPlantedOnSoil_GroundFireLineSurvives`（贴在土上的 19×6 草块烧掉 ≥ 3/4）；既有 24 例只改文案，断言语义不变。
